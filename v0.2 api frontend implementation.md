# v0.2 API Frontend Implementation Guide

This guide explains how to implement the multi-step, tiered assessment flow introduced in v0.2. Unlike v0.1, this version uses branching logic to reduce the number of questions a user has to answer.

## 1. Core Concept: Stateless Branching
The v0.2 API is **stateless**. The frontend must store the user's answers and send the entire set to the server at each step. The server evaluates the answers and tells you what to do next.

## 2. Implementation Flow

### Step A: Fetch the Schema (Optional but Recommended)
Retrieve the structure of the tiers and dimensions to build your UI dynamically.

**Endpoint:** `GET /api/v0.2/:type/schema`

```javascript
const schema = await fetch(`${API_URL}/api/v0.2/tb40/schema`).then(res => res.json());
// Use schema.tiers to understand the flow (binary, ternary, grouping, precision)
```

### Step B: The Evaluation Loop
Your frontend should maintain an `answers` object. Call the `evaluate` endpoint whenever an answer is selected.

**Endpoint:** `POST /api/v0.2/:type/evaluate`

#### Phase 1: Social Energy (Tier 1)
Start with an empty answers object.

**Request:**
```json
{ "answers": {} }
```
**Response:**
```json
{
  "status": "incomplete",
  "next_tier": "tier_1",
  "questions": [...] // The Introvert vs Extrovert question
}
```

#### Phase 2: Talent Orientation (Tier 2)
Submit the answer from Tier 1.

**Request:**
```json
{ "answers": { "tier_1": 1 } } // 1 = Introvert
```
**Response:**
```json
{
  "status": "incomplete",
  "next_tier": "tier_2",
  "questions": [...] // The Karsa vs Cipta vs Rasa question
}
```

#### Phase 3: Group Specific Deep-Dive (Tier 3)
Submit the answers from Tiers 1 and 2. The API will now determine which specific trait questions are needed.

**Request:**
```json
{ "answers": { "tier_1": 1, "tier_2": 2 } }
```
**Response:**
```json
{
  "status": "analyzing",
  "next_tier": "tier_3",
  "group": { "id": "berpikir", "label": "Cerdas" },
  "questions": [...] // 3 specific questions for the "Cerdas" group
}
```

#### Phase 4: Final Result
Submit all answers including the specific Tier 3 scores.

**Request:**
```json
{ 
  "answers": { 
    "tier_1": 1, 
    "tier_2": 2, 
    "tier_3": { "q6": 80, "q11": 90, "q8": 70 } 
  } 
}
```
**Response:**
```json
{
  "status": "complete",
  "result": {
    "primary_group": "Cerdas",
    "description": "...",
    "traits": [...] // Array of detailed trait metadata
  }
}
```

## 3. Precision Mode
If the user wants a more accurate result (the full 40-pillar analysis), you can trigger "Precision Mode" by adding `request_precision: true` to the payload.

**Request:**
```json
{ "answers": { ... }, "request_precision": true }
```
**Response:**
```json
{
  "status": "precision_requested",
  "next_tier": "tier_4",
  "questions": [...] // All 40 questions from v0.1
}
```
*Note: After collecting Tier 4 scores, you should submit them using the v0.1 `/calculation` endpoint to get the full SVG and detailed report.*

| **Tier 1** | Binary | Introvert vs Extrovert | Show 1 question |

## 5. React Best Practices
1. **Local State**: Use `useState` or `useReducer` to track the `answers` object.
2. **Persistence**: Use `localStorage` to save the `answers` so users can resume their assessment later.
3. **Dynamic Rendering**: Use a "Step" component that renders different question types (Binary, Ternary, Likert) based on the `next_tier` returned by the API.
