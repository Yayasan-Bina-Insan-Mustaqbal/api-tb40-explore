# Devlog 009: Tiered Assessment (v0.2) Implementation
**Date:** 2026-06-14
**Status:** Multi-Step Branching Logic Integrated

## Changes
We have implemented the next major version of the assessment logic: **v0.2 Tiered Assessment**.

### 1. Hierarchical Question Structure
- Created `api/v0.2/tb40/questions.json` and `api/v0.2/tb40anak/questions.json`.
- Questions are now organized into **4 Tiers**:
  - **Tier 1**: Introvert vs. Extrovert (Binary).
  - **Tier 2**: Karsa vs. Cipta vs. Rasa (Ternary).
  - **Tier 3**: Group-specific deep dive (determines primary group and traits).
  - **Tier 4**: Precision mode (optional full 40-question set).

### 2. Stateless Evaluation Engine
- Implemented `services/calculation_v2.js` using a decision tree model.
- The engine is **stateless**: the frontend holds the intermediate answers and submits them to the API.
- The API responds with the `next_tier` of questions or a `complete` status with results.

### 3. API Enhancements
- **New Endpoints**:
  - `GET /api/v0.2/:type/schema`: Returns the tiered structure for dynamic UI building.
  - `POST /api/v0.2/:type/evaluate`: Accepts a JSON payload of answers and returns the evaluation status.
- **OpenAPI Update**: Updated `public/api/swagger.yaml` to include v0.2 specifications.

### 4. Verification
- Created `__tests__/v0.2_evaluate.test.js` covering the full multi-step flow.
- All **18 tests** (v0.1 + v0.2 + Utilities) are passing.

## Implementation Choice: Stateless vs. Stateful
We chose the **Stateless REST** approach where the frontend stores the progress. This avoids the complexity of session management/databases on the server while allowing the frontend to easily resume or restart assessments.

## Next Steps
- Implement "Precision Threshold" logic: automatically trigger Tier 4 if the difference between Tier 2 traits is < 10%.
- Add more granular detail to the `complete` result in `v0.2`.
